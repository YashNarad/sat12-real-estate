# SAT12 Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the verified SAT12 desktop/mobile property-results shell with navigation, filters, typed Nagpur data, loading and empty states, and a responsive three-column listing grid, without map integration.

**Architecture:** A client page composes stateless display components around serializable `PropertyFiltersState` and a pure `filterProperties` function wrapped by `useFilteredProperties`. Mock properties are injected into the page rather than imported by UI or filtering code, preserving the backend boundary. Stage 1 reserves the desktop map column with an accessible preview panel but installs no Leaflet packages and contains no map implementation.

**Tech Stack:** Next.js App Router, React, TypeScript, Tailwind CSS, Vitest, Testing Library, Lucide React.

**Spec:** `docs/superpowers/specs/2026-10-09-sat12-property-search-design.md`

## Global Constraints

- Use SAT12 red `#DC0011`, charcoal `#18181B`, secondary text `#71717A`, border `#E4E4E7`, canvas `#F7F7F8`, and white `#FFFFFF`.
- Desktop content reserves approximately 30% for the future map and 70% for results; results use three columns on wide desktop.
- Mock property images are references stored in `data/properties.ts` and point to local, project-owned architectural placeholders in `public/images/properties/`.
- Every property declares `listingIntent: 'Buy' | 'Rent'`; the intent filter must use that field rather than acting as display-only state.
- Filtering accepts an arbitrary `Property[]`; it must not import the mock source.
- Loading and zero-result outcomes must give users clear, accessible UI.
- Do not install or implement Leaflet, authentication, payments, or Supabase in Stage 1.
- Stage 2 map updates will consume memoized filtered properties, use clustering, and perform bounds filtering only when “Search as I move the map” is enabled.

## Review Focus

- A whitespace-only query behaves like no query rather than hiding every property; covered in Task 2.
- A property on an exact budget boundary remains included; covered in Task 2.
- Multiple active filters combine with AND semantics; covered in Task 2.
- A loading result never announces a false zero-result state; covered in Task 4.
- A zero-result state offers a working filter reset; covered in Task 4.
- Sorting, grid/list presentation, and favorites update real local frontend state; covered in Task 4.
